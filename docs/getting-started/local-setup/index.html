Local Setup

The continuum-local-setup repo gives you a single docker compose up that launches the complete Project Continuum stack — infrastructure services, platform backend, browser IDE, and feature workers — all wired together and ready to go.

🐳 Docker onlyNo builds

No builds. No cloning five repos. Just Docker.

Prerequisites​

🐳Docker
20.10+
🧩Docker Compose
v2.0+
🧠RAM
8 GB available for containers
💾Disk
~5 GB for images + volumes

Quick start​

  1. Clone the repo and start the stack:

    git clone https://github.com/projectcontinuum-org/continuum-local-setup.git
    cd continuum-local-setup/docker
    docker compose up -d

  2. Verify everything is running:

    docker compose ps

    All services should show running (the temporal-search-attributes-init container exits after setup — that's expected).

  3. Open the Continuum Workbench. Example workflows are pre-loaded under /home/node/example-workflows/.

Stop everything:

docker compose down       # keep data
docker compose down -v    # also remove volumes

What's inside​

The compose stack has three layers: infrastructure, platform services, and feature workers.

Infrastructure services​

ServicePortPurpose
PostgreSQL35432Database backing Temporal's workflow state and history
Temporal7233Durable workflow execution engine — orchestrates node-by-node execution, handles retries and crash recovery
Temporal UIlocalhost:38081Inspect running workflows, view execution history, debug
Kafka (3-node KRaft cluster)39092–39094Carries real-time node execution events from workers to the browser
Schema Registrylocalhost:38080Avro schemas for Kafka messages
Kafka UIlocalhost:38082Browse Kafka topics, messages, consumer groups
Mosquitto31883 (TCP), 31884 (WS)MQTT broker — last hop pushing execution events to the browser over WebSockets
MinIOlocalhost:39000 (API), localhost:39001 (Console)S3-compatible storage for Parquet data files passed between nodes

Platform services​

ServicePortPurpose
continuum-api-serverlocalhost:8080REST API — workflows, node registry, execution trigger. Single entry point for the workbench UI
continuum-message-bridge—Kafka-to-MQTT bridge for live browser updates
continuum-workbenchlocalhost:3002Browser IDE — Eclipse Theia + React Flow canvas

Feature workers​

ServiceNodesPurpose
continuum-feature-base16 nodesCore analytics — table ops, filtering, REST, scripting, anomaly detection
continuum-feature-cheminformaticsRDKit nodesMolecular descriptors and cheminformatics operations

Want AI nodes? Add the continuum-feature-ai worker image to the compose file for LLM fine-tuning with Unsloth.

Troubleshooting​

Containers keep restarting?

Check logs: docker compose logs <service-name> --tail 100

Temporal not starting?

PostgreSQL needs to be healthy first — give it 30–60 seconds on first run.

Workbench shows connection errors?

The API server may still be starting. Wait until docker compose ps shows all services as running.

Out of memory?

Kafka + Temporal + all services need ~6–8 GB. Increase Docker's memory limit in Docker Desktop settings.

See the full continuum-local-setup README for more detail.
